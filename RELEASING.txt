systemInfo release workflow

./build.sh is the normal distribution build. It increments the highest published/local
numeric version and build, uses the existing Developer ID team F57QJC4XU3 and bundle
identity danielninetyfour.systemInfo, preserves nested entitlements, submits to Apple using existing
Keychain profile notary, staples, validates and assesses before publication.
The pinned Sparkle 2.10.0 signer is invoked only by signing.swift with a verified
in-memory key via stdin. The helper disables Keychain UI before accessing the
existing local.swissKnife account, fails closed if access is denied, and performs
public-key-only signature verification. No keys are created, rotated, persisted,
or passed in argv; Keychain ACLs and permissions are never changed. The normal
build checks access before building, and never retries an inaccessible key.
Distribution builds disable development-only base-entitlement injection. Explicit
SystemInfo-Release.entitlements and Widget-Release.entitlements preserve the
existing user-selected read-only capability and widget sandbox without get-task-allow.
The release workflow checks both targets before notarization.
The interrupted 1.4 (build 5) artifact lacked these capabilities and was never
submitted or published; 1.3 was rejected by Apple and is retained as evidence.

Output: build/systemInfo.app and immutable build/releases/<version>/systemInfo.app.
Each immutable directory includes release.json, notarization.json, notarization.zip,
systemInfo-<version>.zip and a signed appcast.xml. Existing directories/assets are never
overwritten. Apple submissions and GitHub drafts remain available if a stage fails.
Do not blindly retry an interrupted notarization; inspect its recorded ID/history.

Binary releases are published to ngzhenghui94/homebrew-tap (systeminfo-v<version>).
The appcast and cask alone are committed through the app-local .release/update-tap
clone, fetched/rebased on origin/main before normal push. Authored source is never
copied into that public artifact repository. No installation occurs during building.
Installed-app/UI smoke checks are separate. Minimum macOS remains 26.1.

Check for Updates in the app menu is manual-only. Sparkle automatic downloading,
background checking and system profiling are disabled even for persisted preferences.
Signed appcasts and EdDSA archives are required before extraction; Developer ID and
notarized bundle validation remains enabled. Installation waits for outstanding
operations and blocks new privileged operations until relaunch/cancellation.

./build.sh --selftest checks version ordering and rejects unsafe release names/builds.
Tests/UpdatesTests.swift exercises manual checks, operation draining and cancellation
without opening the app or changing system settings. The normal build compiles and
runs these native safety checks before submitting the signed app to Apple.
python3 -m unittest discover -s Tests -p test_release.py checks capability retention
and rejection of missing widget sandbox or development-only signed entitlements.

python3 -m unittest discover -s Tests -p 'test_release*.py' runs release-script
regression checks without accessing signing keys.

Recovery does not rebuild or re-read signing keys:
  ./build.sh --prepare-feed VERSION PUBLIC_ARCHIVE_SIGNATURE
validates the existing signed, stapled, accepted artifact and verifies the archive
signature against the pinned public key, then writes an unsigned appcast exactly
once. The authorized parent batch signer signs that appcast in place.
  ./build.sh --publish VERSION
public-verifies both signatures and exact feed version/build/URL/archive length,
then runs the same immutable publication, checksum checks, tap push and app
promotion as the normal build. Existing appcast files are never overwritten by
prepare-feed; failed drafts/unfinished tap changes must be inspected, not retried.
Neither recovery command accesses a private key or bypasses signature checks.
